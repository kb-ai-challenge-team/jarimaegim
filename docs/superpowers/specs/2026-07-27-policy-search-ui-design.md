# 정책 탭 의미 검색 UI 설계 스펙

기준일: 2026-07-27
대상: `components/Workspace.tsx`(`FundingView`), `lib/api.ts`, `app/globals.css`
선행: `2026-07-27-policy-kb-rag-design.md` (검색 계층은 이미 구현·배포됨)

---

## 0. 문제

`/api/v1/knowledge/search`가 운영에서 동작하지만 UI에서 닿을 길이 없다. 정책 탭은 인덱스의 200건을 접수마감 순으로 나열할 뿐이라, "임차료 지원"을 찾는 사용자가 제목에 그 단어가 없는 `중소기업육성기금` 공고에 도달할 방법이 없다.

## 1. 확정 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | 로컬 필터가 아니라 **의미 검색**을 붙인다 | 사용자 결정. 단어 일치로는 못 찾는 공고를 찾는 것이 목적이다 |
| 2 | **유사도를 렌더하지 않는다** | 사용자 결정. 공고 옆의 숫자는 '적합도'로 읽힌다. 유사도는 질의와의 유사성일 뿐 자격과 무관하다 |
| 3 | **제출에서만** 서버를 호출한다 | 입력마다 호출하면 글자 하나가 유료 임베딩 1회다. 디바운스도 두지 않는다 — 명시적 제출이 비용 모델과 맞는다 |
| 4 | 검색은 `kind=PROGRAM`으로 고정한다 | KB상품은 별도 탭이 있다 |

## 2. 배치와 동작

`FundingView`(`/plan/funding`)의 `PageHeading` 아래에 `<form role="search">` 한 줄.

질의에는 케이스의 자치구를 `district`로 함께 보낸다. 서버가 이를 `["서울","전국"]` 지역 필터로 바꾸므로, 타 지역 공고가 상위에 끼는 일이 줄어든다. `FundingView`는 `district` prop을 하나 더 받는다.

## 3. 상태

| 상태 | 화면 |
|---|---|
| 입력 전 (`idle`) | 기존 목록 그대로 |
| 검색 중 (`loading`) | 스켈레톤 |
| 결과 있음 (`success` & items>0) | 결과 섹션 + "전체 목록으로" |
| 결과 0건 | "검색어와 충분히 관련된 공고를 찾지 못했습니다" |
| `integration_pending` | "의미 검색이 아직 연결되지 않았습니다" |
| `unavailable` | "근거 검색이 지연되고 있습니다" |

**마지막 셋을 하나로 뭉치지 않는다.** 연동이 안 된 것과 정말 없는 것과 일시 장애는 사용자가 취할 행동이 다르다.

## 4. 결과 카드

목록 카드와 다른 모양이어야 한다. 목록은 나열이고 검색 결과는 근거 등급 `C`가 붙은 판단 재료다.

담는 것: 제목 · 기관 · provider 배지 · `excerpt`(원문 발췌, 인용 표시) · `matched_conditions` · `unknown_conditions` · `ProvenanceBar`.

담지 않는 것: `similarity`. 상위부터 나열되는 것으로만 드러난다.

**공식 원문 링크는 담지 않는다(2026-07-28 변경).** 사용자 요청으로 원문 이동 기능을 앱 전체에서 제거했다. `official_url`은 계속 수집·저장되고 인덱싱 조건(https 검증)으로도 남지만 화면에는 노출하지 않는다. `ProvenanceBar`의 출처명·기준일·신뢰도·한계 표시는 그대로이므로 불변조건 3은 유지된다 — 사라진 것은 출처 표시가 아니라 원문에 도달하는 경로다.

## 5. 접근성

`role="search"`, 시각적으로 숨긴 `<label>`, 결과 개수를 `aria-live="polite"`로 알린다.

## 6. 테스트

`flow-check.mjs`는 무키 머신에서 `integration_pending`이 정상이므로 "결과가 나온다"를 단언할 수 없다. **검색창이 존재하고, 제출해도 에러 없이 상태 문구가 뜬다**까지만 검증해 기존 무키 안전상태 회귀선을 깨지 않는다.

## 7. 부록 A 대조

| 불변조건 | 이행 |
|---|---|
| 1. 날조 금지 | 미연동·지연·0건을 각각 다른 문구로. 빈 결과를 목록으로 채우지 않는다 |
| 2. 등급 | 결과는 `C`. 유사도 수치를 화면에 두지 않아 점수로 오해될 여지를 없앤다 |
| 3. 출처 표시 | 결과마다 `ProvenanceBar` |
| 4. AI는 설명, 코드는 계산 | 이 화면은 LLM을 부르지 않는다. `matched_conditions`는 서버의 결정론적 비교 결과를 그대로 렌더할 뿐이다 |
| 6. 서울 스코프 | 케이스 자치구를 넘겨 서버가 서울·전국으로 좁힌다 |
